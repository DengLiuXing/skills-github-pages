# 本周探索记录：从零搭建世界时钟，摸索 AI 辅助开发的个人节奏

在上一周的 Vue 框架开发过程中，我对 Vue 框架产生了一些进一步的疑问和想法。因此，这周我从零开始，借助 AI 逐步搭建了一个世界时钟网页。项目本身不大，但在这个过程中，我一边补 Vue 与 JS 的基础，一边逐渐摸索出了适合自己习惯的 AI 辅助开发方式——这大概是本周最大的收获。

## 1. 世界时钟：从 MVP 长出来的项目

这周的项目是一个显示世界时钟的网页，从 MVP 起步，一路长成了像样的东西：

*   **起点很简陋**：最初的 MVP 只是把浏览器本地时间复读一遍，被我称作"无用产品"。它不解决任何问题，唯一目的是跑通脚手架，练练 `ref`、`setInterval` 和生命周期。
*   **真正的转折**是接了云端授时：算出 `offset = 服务器时间 - Date.now()`，本地每秒走秒、每 60 秒重校一次，断网则降级成本地时间并标注"未校准"。到这一步它才算是个正经工具。
*   **形态几经变化**：时区从好几排的列表改成轮盘式卡片，支持拖拽自定义顺序，最后还加了 3D coverflow 效果。中途为"永远插不到最后一位"的问题，干脆引入了卡片抽象层——列表里装的是"卡片"，至于显示时钟还是显示添加按钮，按类型渲染，问题反而自己消失了。

技术上也有硬仗：动画卡顿那次叠加了五个原因（每帧全量重渲染、`findIndex` 的 O(n²)、强制同步布局等），最后用 rAF 直驱 DOM 才彻底解决。

> **总结**：研究了 Vue 的基础语法，学会了组件传参方式，也掌握了 JS 中变量、简单逻辑和函数的基本用法。

## 2. AI 辅助开发：找到自己的节奏

在使用 AI 开发的过程中，我逐渐摸索出适合我个人习惯的工作方式：**自行设计架构，然后从最小可行性产品出发，逐步挖掘需求并迭代改进。**

这种方式让我能更好地把握项目整体，明确后续的优化方向。虽然进度可能不如完全由 AI Agent 自主开发快，但**这种方式让我感觉更舒适、更有趣**。

特别是在**需要项目基础或创新性较强**的场景下，我更倾向于采用这种开发方式。

至于 AI Agent 自主开发，我承认它确实具备强大的能力，但我更多将其视为**一次性工具**使用，而非盲目应用到需要长期优化和迭代的项目上。项目后半段涉及较复杂的部分时，我会更多地借助 AI 来实现具体需求和优化代码——但架构和方向，还是握在自己手里。

> **总结**：AI 用来提速，不用来交出方向盘；架构自己设计、需求自己挖掘，是我目前最舒服的节奏。

## 3. 不足与下一步

我也意识到，目前对 Vue 框架的学习仍比较浅层，对 JavaScript 的理解也有待加深，因此在开发过程中对不少参数和特性仍感到困惑——比如那些"能跑但说不清为什么"的地方，正是接下来要补的。

新学期开始后，我计划：

*   **开始学习 Go 语言**；
*   **逐步补全 JavaScript（包括 Vue）的相关知识**；
*   **在后续开发小工具时继续使用它们**，在实践中把短板补上。

> **总结**：方向已经明确——Go 开新线，JS/Vue 补齐，小工具继续做下去。
