> [!summary]
> 让绿联 AX900（AIC8800D80）这张 USB 网卡在树莓派 Linux 6.18 上跑起来。
> 官方驱动只声明支持到 6.14，编译直接失败；社区补丁又真假混杂。最后走通的路子是**用已适配新内核的社区 fork，再补上被精简掉的 USB 设备 ID**。全程实测通过。

**适用**：UGREEN AX900 / CM763（AICSemi AIC8800D80 芯片）
**环境**：树莓派 Debian，内核 `6.18.39+rpt-rpi-v8`，aarch64

---

## 一、方案选型（先看这个，少走弯路）

| 来源 | 状态 | 结论 |
|---|---|---|
| 绿联官方驱动 `aic8800_linux_driver`（2025.06） | 声明支持内核 6.14 | 6.18 编译失败，需手工补丁 |
| 社区博客补丁 | 真假混杂 | **只当错误清单参考，不要照抄**（见下） |
| GitHub fork `goecho/aic8800_linux_drvier` | 已适配 6.17+，持续维护 | ✅ **推荐，本文主线** |

### ⚠️ 如何辨别社区补丁里的 AI 幻觉

社区博客常见的"假修复"，鉴别方法：

- `#define del_timer(timer) timer_delete(timer)` 且阈值写成 `>= 6.0` —— `timer_delete` 是 6.15 才引入的，6.0~6.14 上这么改会直接编译失败；而 6.15+ 内核自己保留了 `del_timer` 兼容宏，纯属多余。
- `#ifndef from_timer #define from_timer(...)` —— `from_timer` 自内核 4.14 起就存在，这段永远不会生效。
- 所有版本阈值一律写 `KERNEL_VERSION(6,0,0)` —— 没核对 API 实际引入版本，典型 AI 生成特征。
- 现象列表里提到的错误，修复方案里却没有对应条目 —— 前后不是一套东西。

**正确姿势**：拿博客当"会踩哪些坑"的清单，修复代码以上游内核源码为准（`https://raw.githubusercontent.com/torvalds/linux/vX.Y/` 直接查 API 现状）。

## 二、环境准备（编译前置条件）

```bash
sudo apt update
sudo apt install -y build-essential bc bison flex libssl-dev kmod unzip
apt-cache search linux-headers | grep <你的内核版本>      # 先探测包名
sudo apt install -y linux-headers-$(uname -r)            # 版本必须精确匹配
```

### ⚠️ 头文件版本必须与 `uname -r` 精确一致

`apt install linux-headers-rpi-v8` 这类元包可能拉到不同版本，装完必须验证：

```bash
ls -l /lib/modules/$(uname -r)/build/Makefile    # 存在且指向 /usr/src/<精确版本>
```

### ⚠️ 内核 headers 会硬编码编译器

headers 的 Makefile 可能写死 `CC = gcc-XX`（如 gcc-12/gcc-14），系统没装就报 `/bin/sh: 1: gcc-XX: not found`（错误 127）。照方抓药：

```bash
grep -n "^CC\b\|^HOSTCC" /lib/modules/$(uname -r)/build/Makefile   # 看要哪个版本
sudo apt install -y gcc-XX
```

### ⚠️ 本机编译，不要交叉编译

驱动 Makefile 平台段（`CONFIG_PLATFORM_UBUNTU=y`）会自动推导：

```
SUBARCH = $(shell uname -m | sed ... -e s/aarch64/arm64/)
```

aarch64 上 `ARCH` 自动变 `arm64`。交叉编译还得凑齐工具链 + 内核 `Module.symvers`，纯属自找麻烦。

## 三、拿到社区 fork 并做兼容性核对（关键步骤）

```bash
git clone https://github.com/goecho/aic8800_linux_drvier.git
```

拿到 fork **不要直接编**，先核对四件事。

### 3.1 USB 设备 ID 是否覆盖你的卡

AIC8800 是双模式设计（先存储后 WiFi），有两个关键 VID/PID：

| 阶段 | VID:PID | 由谁处理 |
|---|---|---|
| U 盘模式 | `a69c:5721`（AIC）/ `a69c:5724`（**绿联定制**） | udev 规则 eject |
| 初始 WiFi 模式 | `a69c:8800` | aic_load_fw 下载固件 |
| **最终工作态** | **`368b:8d88`** | **aic8800_fdrv 必须匹配** |

核对命令：

```bash
grep -n "USB_VENDOR_ID_AIC\|USB_PRODUCT_ID_AIC" drivers/aic8800/aic8800_fdrv/aicwf_usb.h
grep -n "USB_DEVICE(" drivers/aic8800/aic8800_fdrv/aicwf_usb.c
```

### ⚠️ 本案例踩的最大坑

fork 精简掉了 `368b:8d88`（绿联旧包有）。驱动加载固件后设备会重枚举成 `368b:8d88`，ID 表没有它就没人接管，`wlan` 接口是空壳。
**最终实测以 dmesg 里重枚举后的 PID 为准**（`Product: AIC 8800D80`，`idVendor=368b`）。

### 3.2 需要补的三处（本案例实测必改）

```
① tools/aic.rules        追加绿联 5724 存储模式 eject 规则（否则插卡停在 U 盘模式）
② aicwf_usb.h            #define USB_PRODUCT_ID_AIC8800D88  0x8d88
③ aicwf_usb.c            ID 表加 {USB_DEVICE(USB_VENDOR_ID_AIC_USB, USB_PRODUCT_ID_AIC8800D88)}
                         chipmatch 的判断里也加 || pid == USB_PRODUCT_ID_AIC8800D88
```

### ⚠️ 确认 ID 表走的是哪个编译分支

fork 里 `CONFIG_USB_BT=y`（`aic8800_fdrv/Makefile`），ID 表实际走 `#else`（BT）分支。补 ID 时要加在该分支内，加到另一个分支等于白加。

### 3.3 固件是否齐全

```bash
diff -r <旧官方包>/fw/aic8800D80 <fork>/fw/aic8800D80
```

两包固件目录都只有 `aic8800D80`；fork 的 `fmacfw_8800d80_u02.bin` 更新，其余一致。

### 3.4 udev 规则 diff

```bash
diff <旧包>/tools/aic.rules <fork>/tools/aic.rules
```

## 四、编译

```bash
cd aic8800_linux_drvier/drivers/aic8800
make -k 2>&1 | tee ~/aic_build.log
grep -nE "error:|Error " ~/aic_build.log
```

### ⚠️ 用 `make -k` 一次暴露全部错误

不加 `-k` 遇到第一个错误就停，一个错误来回一轮；`-k` 让它编完所有文件，一次看完。

### ⚠️ warning 可以忽略的判据

`-Wmissing-prototypes`（上百条）、`-Waddress`、`-Wimplicit-fallthrough`、`-Wrestrict`、`Skipping BTF generation ... unavailability of vmlinux` —— 全是厂商代码历史遗留，正常。
**判成功只看**：`LD [M] xxx.ko` + `MODPOST` 无 error + `make` 退出码 0。

### ⚠️ 编译后、插卡前，用 modinfo 验证 ID 已编入

```bash
modinfo ./aic8800_fdrv/aic8800_fdrv.ko | grep -i 8d88
# 期望出现: alias: usb:v368Bp8D88d*...
```

没有这行说明改的文件没生效，别往下走。

## 五、安装与加载

```bash
sudo make install                          # 装到 /lib/modules/$(uname -r)/kernel/... 并 depmod
sudo modprobe cfg80211
sudo modprobe aic_load_fw                  # 固件加载器，先装
sudo modprobe aic8800_fdrv                 # WiFi 驱动
lsmod | grep aic
```

**然后再插网卡**（驱动先注册 USB 监听，插卡时 udev 自动 eject 切模式）。

### ⚠️ 初始化流程是三段式，别中途误判失败

```
插卡 → a69c:5721/5724 (U盘模式，udev eject)
     → a69c:8800 (WiFi 模式，aic_load_fw 下载固件，dmesg 会刷 rd_version_val/app_cmp)
     → 368b:8d88 (工作态，aic8800_fdrv 接管)  ← 这一步完成才有 wlan 接口
```

期间 dmesg 会有一次 USB disconnect + 重枚举，**是正常流程不是故障**。

### ⚠️ 升级已加载的模块要先 rmmod

```bash
sudo rmmod aic8800_fdrv aic_load_fw   # 卸载旧的，否则 make install 后 modprobe 的还是旧版
```

## 六、验证

```bash
lsusb -t                # 期望: Driver=aic8800_fdrv
dmesg | tail -40        # 期望: New interface create wlan1 / HT,VHT,HE supp
ip link                 # 期望: 多出 wlan1（MAC 是 AICSemi 的 OUI，与板载网卡不同段）
nmcli dev wifi list ifname wlan1
nmcli dev wifi connect "SSID" password "密码" ifname wlan1
```

### ⚠️ 分清板载网卡和 USB 网卡

树莓派内置网卡也叫 wlan0，且 MAC 与 eth0 连号（板载 MAC 段）。USB 网卡插上后是 **wlan1**，MAC 是 AICSemi OUI。看 MAC 前缀判断，别看接口名猜。

## 八、常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `gcc-XX: not found`（错误 127） | headers 硬编码编译器未安装 | 装 `gcc-XX` |
| `implicit declaration of function 'wakeup_source_create'` | 6.16+ 移除旧 API | `rwnx_wakeup_init` 改用 `wakeup_source_register(NULL, name)` |
| `too few arguments to 'cfg80211_rx_spurious_frame'` | 6.15+ 加 radio_idx | 换已适配的 fork 或改签名 |
| `initialization ... incompatible pointer`（set_wiphy_params） | 同上 | 同上 |
| 插卡没反应 / lsusb 只有 U 盘 | udev 缺 5724 规则 | 补规则 + `sudo udevadm control --reload` |
| wlan 接口出现但扫不到网络 | 驱动没接管重枚举后的 8d88 | 补 ID 表（三处） |
| modprobe 报 `Unknown symbol` | 内核版本与 ko 不匹配 / GPL 符号问题 | 确认用当前内核编译 |

## 附：绿联官方驱动路线（内核 ≤ 6.14 时可用，如 x86 Ubuntu 22.04 / 6.8）

1. `sudo bash install_setup.sh` → `cd drivers/aic8800` → `make`
2. 需要的补丁（6.8 实测只差一个）：
   - `aic8800_fdrv/rwnx_wakelock.c`：`rwnx_wakeup_init` / `rwnx_wakeup_deinit`
     加 `LINUX_VERSION_CODE >= KERNEL_VERSION(6,16,0)` 分支，改用
     `wakeup_source_register(NULL, name)` / `wakeup_source_unregister(ws)`
3. 装编译器：Ubuntu 22.04 + HWE 6.8 内核需 `sudo apt install gcc-12`（headers 写死 gcc-12）
4. 卸载：`drivers/aic8800` 下 `make uninstall`，回上级目录 `sh uninstall_setup.sh`

> ⚠️ **fork 与官方包不通用**。fork 把 `radio_idx` 等新 API 写死，只能在 6.15+ 编译；官方包+补丁适用于旧内核。两台机器分别用两套源码，别混。
