# 本周探索记录：从 Live2D-Agent 探索到 Gazebo 机器人学习

> [!note]
> 这周前几天，我遇到了一些挫折：起初我以为自己能开发一个基于 Agent 生态的桌宠，于是设计了架构，也让 AI 生成了好几版作品。但最后，要么出现各种难以调和的问题，要么框架过于复杂让我无从下手，最终我暂停了这个计划。我想，失败的原因是目前还缺少 Agent 的使用经验，暂时没有较为完美的方法使用编程语言与其交互。  
> 
> 接下来的几天，我一边学习 Gazebo 的操作，一边加深对 OpenCode 的理解。目前，我已经了解了 SDF 在 Gazebo 中的作用，以及模型的基本构成。

## 1. Live2D-Agent：一次从愿景到暂停的探索闭环
本周在 Live2D-Agent 项目上的经历，恰好构成了一个"探索—收敛—止损"的完整闭环：
*   **原始构想（07-16）**：受 airi、NagaAgent 两个"巨石架构"桌宠启发却心生抵触，我提出"大脑外包、本地只做画板"的轻量理念，并进一步延伸为 **VSCode 式微内核 + 插件生态**——主程序只提供画布与事件总线，STT/TTS/Agent 全部下沉为插件，主打低门槛与开放生态。
*   **务实收敛（07-21）**：放弃插件式复杂架构，落地为**云服务主导**的轻量方案（FastAPI + 工厂模式 + 小米 MiMo ASR/TTS），核心四原则——解耦、标准、务实、可扩展。这是把宏大愿景压缩成"先跑起来"的务实一步。
*   **踩坑与暂停（07-22）**：用 AI 辅助搭好后端后，发现程序存在严重问题却缺乏有效调试手段。反复权衡后，我决定**暂时搁置开发**，转向研究 OpenCode 并为其编写个性化前端。与其在卡点死磕，不如及时换轨。
> **总结**：目前还缺少 Agent 的使用经验，暂时没有较为完美的方法使用编程语言与其交互

## 2. Gazebo 仿真环境：从"调通"走向"入门"
上周在 WSL 中完成 Gazebo 安装后，本周的重点变成了让环境真正为我所用：
*   **GPU 渲染排错（07-24）**：WSL 原本自动选择 GPU 输出的设置莫名失效，导致渲染无法正常走显卡。最终通过**强制用环境变量指定 OpenGL 走 GPU 渲染**解决。
*   **Building Robot 入门（07-26）**：基于 SDF 在 Gazebo 中生成了一辆小车，借此理清了基础构成：
    *   **模型骨架**：一个模型是 `<model>`，其下各部件都是 `<link>`，每个部件需具备 `<inertial>`、`<pose>`、`<visual>`、`<collision>` 等属性，并用 `<joint>` 连接。
    *   **尚待理解**：`<world>` 中一整套 `<plugin>` 基础框架（Physics、UserCommands、SceneBroadcaster 系统）目前仍未吃透，留待下周啃下。
> **总结**：学会了 gazebo 模型的基本构成
