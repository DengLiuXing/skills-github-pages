为了补完对 Vue 框架以及 JS 逻辑的认知，我从 MVP 起做了一个显示世界时钟的网页。回头看，这个项目最有意思的地方不是最后的效果，而是它一路上是怎么被"需求"推着变形的。

## 一、起点是个"废话产品"

最开始的 MVP 没有任何云端校准，只是把浏览器本地时间复读一遍——我自己的评价是"无用产品"。它不解决任何问题，存在的唯一目的是**跑通脚手架**，顺便练练 `ref`、`setInterval` 和生命周期。

真正的转折点是从 `fetch` 拉云端时间开始的：算出 `offset = 服务器时间 - Date.now()`，本地每秒显示 `now + offset`，每 60 秒重新校准一次，断网就降级成本地时间并标注"未校准"。到这里它才算个正经东西，加上自由选择时区，需求算是满足了。

时区的下拉列表也省了大事——用 `Intl.supportedValuesOf('timeZone')` 直接拿到浏览器内置的大约 400 个时区，离线可用，不用手写。

## 二、需求一旦开了口子就停不下来

实现完最简单的需求之后，优化思路就源源不断冒出来了。

- **新增按钮该放哪儿？** 一开始它是个孤零零的按钮，后来随着需求变化，我给它找到了更合适的位置。

- **这么多时区怎么展示？** 一开始是好几排的列表，看一眼就眼花。我改成和主流世界时钟工具类似的交互：**轮盘式的横向卡片**，每个卡片都有自己的ID，这样就可以拖拽卡片自定义顺序能。再往后还加了 3D coverflow 效果：容器加 `perspective`，按卡片距中心的偏移算 `rotateY` / `scale` / `translateZ`。中间大、两边倾斜。

- **首尾卡片要居中** 因为 coverflow 天然需要两侧有邻居，所以要给容器补左右 padding。
- **怎么拖动卡片时看起来怪怪的** 看起来只有中间的三个会变化，因为归一化范围太窄，而且位置计算不该"按索引假设坐标"，得读 `offsetLeft`——它是布局值，不受 transform 干扰。

**最大的一次改动是性能问题。** 动画明显不流畅，叠加了五个原因：每帧全量 Vue 重渲染、`findIndex` 的 O(n²) 复杂度、每帧读 `offsetLeft/clientWidth` 触发强制同步布局（layout thrashing）、`preserve-3d` 加在叶子节点阻碍扁平化、还有 `transition` 和逐帧更新打架。最后改成**用 rAF 直驱 DOM**，绕开 Vue 响应式直接写 `style`，偏移只测一次并缓存，rAF 空闲自停，CSS 走 GPU 合成——从"每帧上百次 DOM 重建"降到"每帧几十次字符串赋值"。

> [!note]  
> 值得一提的是，这种问题在去年还得我人工定位完再喂给 AI，AI 才能解决；今年即便是风评一般的混元模型，也能快速把多重问题一起揪出来并修掉。（当时我确实没找出来到底卡在哪，因为其实我也没有深入研究 Vue）

**还有个专门防"无聊的人刷爆内存"的优化。** 要限制卡片数量、禁止重复添加。其实 AI 早就自行处理过，但它当时只允许插 20 张卡，而且选到重复的一点提示都没有，体验很差。我当时的想法是：既然有了拖拽，添加重复卡片本质上就是**把旧的那张"拖"到新卡片的位置**，总数不变。这样卡片上限天然等于世界时区数，不可能无限添加，用户也一眼能理解。

最后的落地方案是"**删旧留新**"：先插入新卡，再把同名的旧卡过滤掉；数量达到时区总数就拒绝添加作为保底。另外还发现一个残留漏洞——卡片里的下拉框改时区照样能造出重复，索性把卡片的时区改成**只读**。这样"改时区"的入口收窄成唯一一条，重复卡在结构上就不可能产生了。

> [!note]  
> 甚至在我录制讲解视频的时候，又发现了一些需求, 比如说要做持久化，要添加筛选和搜索功能

## 三、最漂亮的一步：卡片抽象层

拖拽排序做完后有个死结：插入逻辑是"插到目标卡**前面**"，导致**永远插不到最后一位**。

AI 列了五种补丁方案（上下半区判断、缝隙槽位、容器兜底、容器坐标计算、引入库）。但我借鉴了 C++ 的设计思想：**做一个卡片抽象层，列表里装的是"卡片"这个基类，至于显示时钟还是显示添加按钮，按实际类型渲染**。

落地下来就是判别联合 + 类型分发：

```
tzList: [{ id, type:'clock', tz }, ..., { id:'__add__', type:'add' }]
渲染：v-if="type==='clock'" → ClockCard / v-else → AddCard
```

**一举三得**：添加卡变成了列表的末位成员，拖到它上面就等于插到末尾，末位难题自己消失了（那些中线计算全省了）；添加 UI 从"浮在上方"收进了网格；以后要加统计卡、设置卡，只要多一个 `type` 分支。

## 四、一些体会

- **要架构，不要补丁**。五个补丁方案解决不了的问题，换一个数据模型就自己消失了。与其修补症状，不如让问题不存在。
- **追问到原理层**。像是 `splice` 到底怎么平移中间元素、`onDrop` 里某个变量是不是必需的，每个点挖到底之后，后面写东西心里才有底。
- **边界感**。有次 AI 说"实施"，其实我指的是只做 id 这一步，它却顺手把去重、上限、按钮禁用全做了，被我直接打回。之后约定：**说做哪一步就只做哪一步**，重大改动先问再做。
